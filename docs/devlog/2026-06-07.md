- **Envío masivo:** `scripts/bulk-invite-workshop.mjs` (modos `preview`/`send`), idempotente vía `invitation_log` y reutilizando la lógica del endpoint `send-invitation` (`generateLink` Supabase + Resend con rate limit).
- **Auditoría de la lista (266 pagados):** emails únicos y válidos, 0 duplicados, 0 sin nombre. Excluidos 2 correos internos (`academia@`, `edaza@`) → **264 cuentas creadas + 264 invitaciones, 0 fallos**. Conteos verificados: `profiles` 17→281, `enrollments` (cohort active) 12→276, `invitation_log` 11→275.
- **Plantilla de email mejorada** (`lib/email/invitation.ts`): logo real en el header azul (`brand/logo-light.png`), nombre de programa sin duplicar, y copy reescrito de "enrolamiento seco" a "bienvenida + presentación de plataforma + acceso online". Verificado con preview a inbox propio antes de enviar.
- **Scripts de diagnóstico:** `check-activation.mjs` (34 activados, 31 hoy, 16 onboarding completo), `check-playback.mjs` (0 reproducciones de los nuevos), `find-bad-auth-user.mjs`, `create-test-invite.mjs`, `verify-fix-setup.mjs`.
- **E2E con Playwright** (venv aislado + Chrome del sistema) contra producción: login → set-password → complete-profile → workshop → abrir clase → **video carga OK** (`readyState 4`, HLS Mux 200).
- **Bug encontrado y arreglado:** los IDs semilla del classroom (`d0000…`, `b0000…`, etc.) **no son UUID RFC 4122** (nibbles de versión/variante en 0). Postgres los acepta, pero `z.string().uuid()` los rechaza con **422** en `/api/classroom/progress` (no guardaba avance), `/comments` y `/quiz/submit`. Solución: helper `uuidLike` en `lib/utils/zod.ts` reemplazando `.uuid()` en los 3 endpoints. Commit `f5b6592` + CHANGELOG.
- **Deploy manual a Netlify prod** (`netlify deploy --build --prod`) y verificación en vivo: `progress` → **200** (guardó posición 42s/1.46%), `comments` → **200**, fila en `video_progress` confirmada. Usuario de prueba limpiado.

### Lo que se descartó / caminos que no funcionaron
- **El MCP de Supabase apuntaba al proyecto equivocado.** El `SUPABASE_ACCESS_TOKEN` del `.mcp.json` estaba cruzado (daba `Unauthorized`), así que el MCP consultaba la base de compradores (Encuentro Smart) en vez del classroom. Eso produjo una conclusión **falsa** sostenida durante un buen rato: "el classroom no tiene tablas / la DB está desconectada". El `.env` del repo era correcto desde el inicio. Lección: confié en una herramienta mal configurada en lugar de en lo que el usuario afirmaba. Se resolvió consultando por **REST directo con el service key del `.env`** (PostgREST `to_regclass`/HTTP), confirmando que las tablas sí existen.
- **No hizo falta el PAT nuevo de Supabase** que se llegó a pedir: una vez verificado por REST, las credenciales del `.env` (classroom) + las de `encuentrosmart` (compradores) cubrían todo.
- **Diagnóstico "0 reproducciones = rezago de día 1" era parcialmente erróneo:** el 422 en `progress` estaba suprimiendo el registro de avance. Muy probablemente sí veían clases pero no se guardaba.
- **422 en `onboarding/complete-profile` durante el E2E NO era bug de la app:** fue por datos de prueba basura (string inválido en `linkedin_url`, que exige URL). Con solo campos obligatorios (nombre, teléfono, RUT válido) el flujo pasa.
- **Admin API de Auth reventaba** con `per_page` 50/1000 (`"Database error finding users"`, 500). Causa: un registro corrupto en `auth.users` — la cuenta admin `edaza@` con columnas de token en `NULL` (bug clásico de GoTrue al escanear la fila). Mitigado bajando a `per_page=20` + saltando la página rota y usando `profiles.onboarding_completed_at` como señal de activación.
- **Push a `main` no disparó deploy.** La branch de producción configurada en Netlify (`claude/setup-capital-academy-mvp-e13yU`) **ya no existe** en el repo → auto-deploy roto. Por eso el deploy tuvo que ser manual.
