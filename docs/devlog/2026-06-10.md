## Sesión 14:11

**Contexto**: Se necesitaba cobrar un monto arbitrario (CLP 200.000) sin pasar por el flujo de pago acoplado al Diplomado. Se construyó un sistema de cobro genérico en tres partes (página pública + panel admin + concepto editable), y en el camino se arregló el deploy de Netlify que estaba roto desde antes.

**Lo que se hizo**:

- Página de cobro genérico `/pago/cobro?monto=&sig=` con monto firmado HMAC-SHA256 (`COBRO_SIGNING_SECRET`). El servidor re-verifica la firma antes de cobrar; URL manipulada → rechazo. Archivos nuevos: `lib/cobro/sign.ts`, `app/pago/cobro/page.tsx`, `app/pago/cobro/CobroCheckoutClient.tsx`, `app/api/pago/cobro/route.ts`, `scripts/generate-cobro-link.mjs` (94734f9).
- Los cobros genéricos se insertan en `payments` con `plan = null` (fix del constraint `payments_plan_check`) (98aff63).
- Panel admin `/admin/cobros` (gateado por rol ops/admin): formulario de monto → genera link firmado server-side → copiar. Ítem "Cobros" agregado al sidebar (aac2635).
- Concepto editable y firmado: el subject que se ve en Flow/email se edita desde el panel. Retrocompatible — sin concepto se firma solo `monto` (links viejos siguen válidos); con concepto se firma `monto:concepto` (9c4da3e).
- Fix del deploy de Netlify (roto desde el commit 2602008, anterior a esta sesión): `packages: ["."]` en `pnpm-workspace.yaml` (a2fe08d) + `PNPM_VERSION = "10.30.3"` en `netlify.toml`, la versión nativa del builder (12d78df). Deploy verde.
- Push movido al remoto `edaza-create/capitalacademy`, que es el conectado a Netlify (se autenticó `gh` con esa cuenta).
- `COBRO_SIGNING_SECRET` seteada en Netlify. CHANGELOG y codemap actualizados.

**Lo que se descartó**:

- Pinear `PNPM_VERSION = "11.4.0"` para alinear con el lockfile (95b49ec): el corepack del builder de Netlify no puede cargar pnpm 11 (`ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`). La salida fue usar 10.30.3, la versión nativa del builder.
- Diagnóstico inicial por suposición (versión de pnpm en `netlify.toml`) no bastó; el log real del build mostró el segundo error (`packages field missing or empty` en `pnpm-workspace.yaml`, inválido para pnpm < 10). Moraleja: pedir el log del CI antes de iterar a ciegas.
- `git push` al remoto original `elkisdm/Capitalacademy` desde el shell no-interactivo: colgaba pidiendo credenciales. Se resolvió cambiando de cuenta y de remoto (edaza-create), que además era el correcto para el deploy.
