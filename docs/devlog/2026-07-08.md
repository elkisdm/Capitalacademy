# 2026-07-08

## Sesión 12:00

### Contexto

Un reporte (con captura) indicaba que alumnos matriculados en el Diplomado dejaron de ver ese entorno luego de que se les agregara el nuevo entorno "Capacitación CI". Se investigó si hubo pérdida de acceso.

### Lo que se hizo

- **Diagnóstico en BD (sin pérdida de datos):** consulta vía Supabase confirmó que los 16 alumnos agregados a Capacitación CI mantenían todas sus matrículas en `active` — cada uno conservaba CI (07-jul), Diplomado IV Generación (junio) y, varios, el Workshop Inmobiliario. Era un bug de navegación, no de datos.
- **Causa raíz:** `/classroom` ("Mis programas" del sidebar) no listaba programas: hacía un redirect incondicional a la matrícula activa más reciente (`app/(classroom)/classroom/page.tsx`, `order(enrolled_at desc).limit(1)`). CI, por ser la más nueva, capturaba siempre al alumno. El bug ya existía en silencio (alumnos con Workshop + Diplomado); CI lo hizo visible.
- **Fix (Tier 1 vía spec-flow, change `classroom-multi-program-picker`):**
  - `lib/classroom/queries.ts` — nuevo helper `getActiveEnrollmentsForUser(userId)`. Usa `CONTENT_ACCESS_STATUSES` (`active` + `completed`) en vez de solo `active`, para espejar el gate real de acceso del `[cohortSlug]`.
  - `app/(classroom)/classroom/page.tsx` — reescrita: 0 matrículas → mensaje; 1 → redirect directo (sin cambio para la mayoría); 2+ → grid de tarjetas con la marca de cada entorno (`getBrandByProgramId`); staff → entorno activo.
  - `docs/codemap.md` — fila de `/classroom` actualizada al selector real.
  - `.spec-flow/events.jsonl` + `CHANGELOG.md` (`[Unreleased] > Fixed`).
- **Verificación:** `tsc --noEmit` limpio y `pnpm build` exit 0 (se cumplió la regla de correr `next build`, no solo tsc).
- **Commits + deploy:** `777fcf1` (fix) y `6da1e22` (changelog); push a `work/main` (fork edaza-create). Deploy Netlify verificado en estado `ready` con `6da1e22` en producción.

### Lo que se descartó

- **Hipótesis: el script `scripts/invite-capacitaciones.mjs` borraba matrículas.** Descartada: el upsert solo inserta una fila nueva (`onConflict`), no toca otras.
- **Sospecha de pérdida de datos.** Descartada por la consulta SQL: todas las matrículas seguían `active`.
- **`git push origin main` falló (403):** `origin` apunta a `elkisdm/Capitalacademy`, donde la cuenta `edaza-create` no tiene permiso. Se corrigió pusheando a `work` (fork), que es de donde Netlify despliega. Guardado en memoria para no repetirlo.
- **`netlify api getSite` no devolvió el id:** se obtuvo el `site_id` desde `.netlify/state.json` para listar los deploys.
