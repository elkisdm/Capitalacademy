- **Causa raíz encontrada para el Frente 6** (bug de perfil): `student-profile-client.tsx` (`saveField`) reenvía `full_name`/`phone`/`rut` en cada guardado; el endpoint `app/api/onboarding/complete-profile/route.ts` exige `phone.min(6)` y `rut` válido. Para un usuario staff/ops sin matrícula, esos campos están en `NULL` → se envían vacíos → validación zod falla con 422 → el staff queda bloqueado para editar cualquier campo de su perfil (catch-22). Causa secundaria: la columna `profiles.birthday` no existe en el schema, así que ese campo específico fallaría igual con 500 una vez resuelta la causa primaria.

### Lo que se descartó

- **Lanzar el workflow de planificación paralela con `args` como parámetro separado del tool `Workflow`**: falló dos veces seguidas con `Error: undefined is not an object (evaluating 'args.workstreams.map')` porque los argumentos llegaban al script como string JSON serializado en vez de objeto real — un problema de cómo el tool pasa `args`, no del diseño del workflow en sí. Ambos reintentos (incluso pasando `args` explícitamente en el segundo) fallaron igual.
- **Solución descartada tras el segundo fallo y reemplazada**: en vez de seguir dependiendo de `args`, se reescribió el script del workflow incrustando los 7 briefs directamente como constantes JS dentro del propio script (`WORKSTREAMS` hardcodeado), eliminando la dependencia del paso de argumentos. Esta versión (`plan-pendientes-profe-v2`) sí funcionó al tercer intento.
