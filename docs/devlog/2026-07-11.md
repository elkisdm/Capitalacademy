### Lo que se descartó

- **4 ejecutores murieron simultáneamente por límite de sesión** (reset 2am Santiago) a mitad de la ronda de refinamiento UI. Se verificó el árbol (compilaba limpio, sin nada roto a medias) antes de reintentar; los lotes se relanzaron y completaron sin pérdida de trabajo.
- **Un ejecutor de cierre murió por corte de red transitorio** justo antes de tocar archivos; se relanzó idéntico sin problema.
- **El auditor de bundle sobreestimó el peso del SDK de Fintoc** (dijo 126 KB gzip; el ejecutor verificó que el chunk real es de 966 bytes — un loader que inyecta el script desde el CDN de Fintoc, no un SDK embebido). El import dinámico se aplicó igual como buena práctica, pero la ganancia real de ese lote fue el ISR de `/pago`, no el bundle.
- **Primer push del cierre (`896bb27`) falló el build de Netlify**: se saltó la build aislada antes de pushear (para no interferir con una sesión paralela que trabajaba sobre el mismo working tree en el módulo de conversaciones/comentarios) y un archivo (`sessions-manager-client.tsx`) quedó importando `components/admin/collapsible-section.tsx`, que era código **untracked de esa otra sesión** — compilaba mezclado pero no standalone. Producción no se vio afectada (Netlify mantiene el último deploy bueno). Se corrigió reemplazando el import por un `CollapsibleSection` inline autosuficiente (`e59c599`), verificado con build aislada antes del segundo push.
- **Commit selectivo cuidadoso durante todo el cierre**: al compartir working tree con otra sesión activa, se verificó dos veces (antes de cada commit) que ningún archivo propio importara módulos untracked ajenos, y que archivos "de riesgo" compartidos (`lib/supabase/types.ts`, `admin/lessons/[lessonId]/page.tsx`) no se colaran — se dejaron sin stagear porque pertenecían al trabajo paralelo (migraciones `0065-0067`, foro de comentarios).
