### Lo que se descartó / corrigió

- **El "bloqueante" del 24-jul era un falso positivo.** El subagente de aquella sesión midió `origin/main` = `elkisdm/Capitalacademy`, un **fork personal 364 commits atrasado** con solo 9 archivos de test (de ahí el "main tiene ~13% de cobertura" y el "branch 19 commits sin mergear"). El main real es `work/main` = `edaza-create/capitalacademy`, que ya tenía 142 archivos de test. El branch estaba **2 commits adelante, no 19**. Regla: en este repo `origin` NO es el repo real, siempre comparar contra `work/*`.
- **Correr el coverage sobre `work/main`**: descartado. El branch es exactamente `work/main` + 2 commits, o sea el mismo árbol post-merge, y además es el único que tiene el gate configurado.
- **Poner `packageManager` en `package.json`** como fix del CI: descartado porque Netlify también lee ese campo y hoy construye bien. El fix preferido son dos líneas en el workflow (`with: version:` en `pnpm/action-setup@v4`).
- **Gotcha del shim `gh`**: elige cuenta por el remoto `origin`, ignorando `--repo`. Con dos remotos, `gh pr list --repo edaza-create/...` falla con "Could not resolve to a Repository". Se resolvió con el passthrough documentado (`GH_TOKEN=$(gh auth token --user edaza-create) gh ...`), sin `gh auth switch`.
